## 发现问题列表

### ISSUE-1［低危］HEAD 请求未豁免鉴权，`HEAD /api/blog/says` 返回 401

- **严重度**：低（不影响契约与任何浏览器行为；fetch/XHR 不使用 HEAD）
- **复现步骤**：
  1. `curl -I https://dujiecone.520691.xyz/api/blog/says`
  2. 预期 200，实际 `HTTP/2 401`
- **根因**：`worker/index.ts` 的 `isExempt()`（L205）按字面方法名匹配 `AUTH_EXEMPTIONS`；Hono 的 GET 路由依 HTTP 规范自动兼容 HEAD，但豁免判断未将 HEAD 归一为 GET，导致 HEAD 落入鉴权逻辑返回 401。同源 GET（带或不带 Origin）均为 200 且 CORS 头完整。
- **建议**：豁免匹配时将方法归一化，例如 `const m = c.req.method === 'HEAD' ? 'GET' : c.req.method`，或在豁免列表补充 HEAD 规则。属规范完备性增强，非本轮契约项。

### 说明-1（环境因素，非缺陷）T4 toggle 首轮复测出现 count:2

- **现象**：连续两次 POST /api/blog/like 第二次返回 `liked:true, count:2` 而非 toggle 取消。
- **定位**：本沙箱出口 IP 逐请求轮换（cdn-cgi/trace 采样 10 次命中 5 个不同 IP），访客指纹 = sha256(IP+UA+盐) 随之变化，第二次请求被判为新访客走 INSERT 分支——源码逻辑正确（`existing !== null → DELETE`，且有 `idx_likes_unique` 唯一索引兜底）。
- **实证**：持续发起点赞直至出口 IP 与历史请求重复（同指纹），API 立即返回 `liked:false, count:1`，toggle 双向行为确认无误。真实用户（固定 IP/UA）不受此影响。

### 说明-2（设计内行为）RSS item 链接使用 .html 后缀

- RSS `<link>` 指向 GitHub 端 URL（如 `/posts/blog-comment-system.html`），CF Pages 端会 308 跳转到无扩展名规范 URL。符合「URL 双端」收录设计且跳转链畅通（C4 已验证）。可选优化：RSS 使用 www 端规范链接以减一跳，非缺陷。
