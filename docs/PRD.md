## 1. 产品概述

### 1.1 定位

渡劫code 是面向中文开发者的**浏览器原生 AI 编程工作台**。它完整吸收 AiCode「AI Agent + 终端 + 文件系统」的核心范式，并充分发挥 Web 与云原生的结构性优势：零安装跨设备、云端持久化工作区、全球边缘低延迟、远程 SSH 真实执行后端。产品坚持「模型中立」——用户自行配置 API Key，平台不内置模型、不绑定供应商、不转售模型服务。

### 1.2 与 AiCode 差异化对比表

| 维度 | AiCode（Android） | 渡劫code（Web） | 优势说明 |
|---|---|---|---|
| 使用门槛 | 需下载 APK，依赖 Android 设备 | 浏览器打开即用，零安装 | iOS / PC / 平板全平台可用 |
| 计算环境 | 设备本地 Alpine 容器，受手机性能与存储制约 | 云端虚拟文件系统 + 远程 SSH 后端 | 重任务不消耗本地资源，小屏设备也能跑大工程 |
| 数据同步 | 单设备本地存储，易丢失 | D1 + R2 云端持久化 | 换设备无缝继续，历史不丢 |
| 终端能力 | 本地容器完整 Shell | 虚拟 Shell（云端 VFS）+ SSH 真实后端双模式 | 零配置试错与真实构建两全 |
| 供应商配置 | 三类协议 + 自定义端点 | 同款三类 + 自定义 + 连接测试 + 模型列表自动拉取 | 配置体验更顺、排障更快 |
| 审批机制 | 本地通知一键允许/拒绝 | 站内审批卡片 + 浏览器通知 + 审计日志 | 多端可达、全程可审计 |
| 扩展性 | MCP 协议扩展 | MCP（远程优先，stdio 经 SSH 桥接） | 云端形态下同样开放 |
| 交付迭代 | 需重新安装 APK | 边缘部署即时生效 | 用户始终使用最新版 |

### 1.3 系统组成简览

| 组件 | 职责 |
|---|---|
| 前端 SPA | 工作区 UI（文件树 / Monaco / 终端 xterm.js / 对话面板 / 审批弹窗） |
| Workers 边缘网关 | 认证、LLM 流式代理、工具执行调度、速率限制 |

| F03 | AI 对话式编程 Agent | 以流式对话驱动编程，内置「读文件 / 写文件 / 编辑文件 / 列目录 / 搜索 / 执行命令」工具调用循环，过程可视化、可随时停止、可重新生成。 |
| F04 | Web 工作区 | 提供文件树 + Monaco 多标签代码编辑器，与云端虚拟文件系统实时双向同步。 |

| F06 | 远程 SSH 执行后端 | 经 Cloudflare Worker 的 WebSocket→TCP 代理连接用户自有服务器，网页终端直接操作真实 Linux 环境，AI 命令可路由至该后端执行。 |
| F07 | 危险命令审批 | AI 发起命中高危规则的工具调用时弹出审批卡片，用户一键允许 / 拒绝，全程记录审计日志，不在前台时触发浏览器通知。 |
| F08 | 会话与工作区持久化 | 会话与消息存 D1、文件内容存 R2，刷新或更换设备后完整恢复，支持多会话并存。 |
| F09 | 官方网站 | 提供产品介绍、架构说明、快速开始的落地页，作为产品门面与获客入口。 |

#### F03 Agent 工具调用循环（MVP 工具白名单）

| 工具 | 说明 | 是否需审批 |
|---|---|---|
| `list_files` / `get_file_tree` | 列出目录 / 文件树 | 否 |
| `read_file` | 读取文件内容 | 否 |
| `write_file` | 新建或覆盖写文件 | 覆盖已存在文件时提示确认（P1 起可调） |
| `edit_file` | 基于旧串替换的精确编辑 | 否 |
| `search_files` | 文件名 / 内容搜索（grep 语义） | 否 |
| `run_command` | 在虚拟 Shell 或 SSH 后端执行命令 | 命中危险规则时必须审批 |

**循环机制**：流式接收模型输出 → 解析工具调用 → （危险命令进入审批）→ Worker 执行工具 → 结果回传模型 → 继续下一轮，默认最大 25 轮，用户可中止。

### 3.2 终端方案重点设计（F05 + F06）

Web 端没有本地 Linux 容器，采用**双模式终端**互补：

| 模式 | 虚拟 Shell（默认，零配置） | 远程 SSH 执行后端（真实环境） |
|---|---|---|
| 执行位置 | Cloudflare Worker 内解释器 | 用户自有服务器 |
| 作用对象 | 云端虚拟文件系统（D1 元数据 + R2 内容） | 服务器真实文件系统与进程 |
| 适用场景 | 学习命令、轻量文件操作、随时试错 | 构建、测试、部署、数据库、重依赖工程 |
| 命令范围 | 白名单：`pwd / ls / cat / echo / mkdir / touch / rm / cp / mv / grep / find / head / tail / wc / clear / help`（P1 增加管道、重定向、通配符、环境变量） | 服务器上任意命令 |
| 连接链路 | 浏览器 → Worker HTTP 流式 | 浏览器 xterm.js ⇄ (WSS) ⇄ Worker WebSocket→TCP 代理 ⇄ 用户服务器 sshd |
| 凭据 | 无 | SSH 连接配置（别名 / 主机 / 端口 / 用户名 / 密钥或密码），加密存储 |
| 失败降级 | — | 连接失败时终端提示原因，可切回虚拟 Shell |

**关键设计点**：

1. **危险命令在两种模式下统一走审批**（见 F07），AI 与用户手动执行均适用。
2. SSH 私钥 / 密码与 API Key 同样加密落库；建连时由客户端提供会话解密材料，Worker 仅在内存中使用，断开即焚，**不持久化明文**；推荐用户使用密钥对认证。
3. P1 起支持 VFS 与远程目录互传（上传 / 下载 / 目录同步），使 AI 可在两端无缝搬运文件。

## 5. 非功能需求

### 5.1 安全

| 项 | 要求 |
|---|---|
| 密钥加密 | API Key 与 SSH 凭据采用**零知识加密**：客户端 PBKDF2-SHA256（≥10 万次迭代）从用户口令派生密钥，AES-256-GCM 加密后仅密文 + 盐 + IV 入库；服务端无法解密；提供「仅本地存储」备选模式 |
| 传输安全 | 全站强制 HTTPS / WSS，启用 HSTS |
| CORS | 严格白名单：仅官方域名与 localhost 开发端口 |
| 速率限制 | 基于 KV 滑动窗口：API 默认 60 次/分钟/用户，登录 5 次/分钟/IP，终端命令 120 次/分钟/会话 |
| LLM 代理 | Worker 代理不透传、不落盘用户 Key 明文；错误信息脱敏后返回前端 |
| 审批与审计 | 危险命令必须显式授权，审批记录与命令审计日志入库且用户不可删 |
| 密钥管理 | Cloudflare Workers Secrets 管理平台侧秘密，代码仓库零秘密 |

### 5.2 性能

| 项 | 指标 |
|---|---|
| 边缘部署 | 静态资源与 API 全球边缘分发，就近接入 |
| 首屏加载 | 官网与应用首屏 < 2s（4G 网络） |
| 流式响应 | LLM 首 token < 3s（同区域供应商），逐 token 渲染，随时可停止 |
| 文件操作 | 文件树加载 / 小文件读写 < 500ms |
| 终端体验 | 虚拟 Shell 回显 < 200ms；SSH 终端输入回显 < 150ms（同区域服务器） |
| 大文件 | >1MB 文件走 R2 直传/直读，编辑器不阻塞 |

### 5.3 兼容性

| 项 | 要求 |
|---|---|
| 浏览器 | Chrome / Edge ≥ 100、Firefox ≥ 100、Safari ≥ 16（依赖 WebCrypto、WebSocket、SSE） |
| 设备 | 桌面优先，响应式适配平板与手机（P1 深度优化，P2 PWA） |
| 不支持 | IE 及任何不支持 WebCrypto 的浏览器 |

## 6. MCP 扩展支持设计思路（P1 / P2）

**背景**：MCP（Model Context Protocol）是 AI 工具接入的开放标准，统一「工具 / 资源 / 提示」三类原语，支持后可复用社区海量 MCP Server，是渡劫code 生态竞争力的关键。

**Web 端约束**：MCP 的 stdio 传输依赖本地子进程，浏览器环境不可用；Streamable HTTP / SSE 传输可用。

| 阶段 | 设计 |
|---|---|
| P1：远程 MCP（Streamable HTTP / SSE） | ① 设置页新增 MCP 服务器管理（URL、传输类型、Headers/Token、启停）；② 连接时执行 `initialize` + `tools/list` 并缓存工具 schema；③ Agent 启动时将 MCP 工具合并进工具列表（命名 `mcp__{server}__{tool}`），调用经 Worker 代理，结果回传 Agent 循环；④ 附带支持 `resources/read` 读取资源；⑤ UI 提供工具列表查看与单工具测试调用 |
| P2：stdio 桥接 | 在用户的 SSH 后端服务器上安装并拉起 MCP Server 进程，Worker 经 SSH 通道转发 JSON-RPC，等效将「本地 MCP 生态」接入云端 Agent |
| 安全 | MCP Token 与 API Key 同等加密存储；危险 MCP 工具调用同样进入审批流程；调用记录写入审计日志 |

|---|---|---|---|
| Q1 | 用户认证方式？ | 邮箱魔法链接（无密码）+ GitHub OAuth，JWT 会话存 KV | 规避密码泄露风险，适配全球用户；邮箱密码注册列为 P2 补充 |
| Q2 | API Key 存云端还是本地？ | 默认零知识云端加密（PBKDF2 派生 + AES-GCM，D1 存密文），设置内提供「仅本地存储」开关 | 兼顾跨设备同步与隐私，服务端零知识 |
| Q3 | SSH 私钥/密码如何被 Worker 使用？ | 建连时客户端提供会话解密材料，Worker 内存中解密、断开即焚，不持久化明文；推荐密钥对认证 | 平衡可用性与安全性，并在 UI 明确告知用户 |
| Q4 | LLM 请求走服务端代理还是浏览器直连？ | 默认 Worker 服务端代理（统一流式、限流、审计、规避 CORS）；提供「浏览器直连」备选开关（P1） | Anthropic 直连需 `anthropic-dangerous-direct-browser-access` 头，作为降级路径 |
| Q5 | 虚拟文件系统存储选型？ | D1 存目录树与元数据，R2 存全部文件内容 | D1 适合树状查询，R2 适合大对象与直读 |
| Q6 | 官网域名？ | 先以 Workers/Pages 默认域名上线，同步注册 `dujiecode.com`，注册成功即切换 | 不阻塞上线节奏 |
| Q7 | 商业化与定价？ | 应用免费并开源（MIT），用户自带 Key；官方不提供模型代充/转发服务 | 合规优先，MVP 可承载于 Cloudflare 免费额度 |
| Q8 | 审批超时策略？ | 审批不自动超时放行，挂起至用户处理；页面不在前台时发浏览器通知 | 安全优先，杜绝「默认放行」 |
| Q9 | 多人协作？ | MVP 仅单用户工作区，协作/分享列 P2 | 控制 MVP 范围与数据模型复杂度 |
| Q10 | 云端直接运行用户代码？ | 不在 MVP；执行环境限定「虚拟 Shell + 用户自有 SSH 服务器」 | 规避沙箱逃逸与滥用风险 |
